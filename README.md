## 🚀 Краткое описание

**User Backup Manager** — это автоматизированная система резервного копирования пользовательских данных для Windows, разработанная для корпоративной среды. Приложение обеспечивает централизованное управление резервным копированием профилей пользователей с минимальным вмешательством в их работу.

Система использует Windows Task Scheduler для автоматического выполнения резервного копирования по расписанию и предоставляет механизм централизованного обновления всех компонентов из сетевой папки.

## 🎯 Назначение

Основные цели приложения:

1. **Автоматизация резервного копирования** — пользователи не должны помнить о необходимости создания бэкапов
2. **Централизованное управление** — администраторы могут обновлять конфигурацию и скрипты для всех пользователей
3. **Надежность и отказоустойчивость** — система продолжает работать даже при временной недоступности сети
4. **Минимальное вмешательство** — работа в фоновом режиме без постоянного взаимодействия с пользователем
5. **Адаптивность** — поддержка как стандартных, так и пользовательских директорий для резервного копирования

## ⭐ Ключевые функции

### 🔄 **Автоматическое резервное копирование**
- Планирование через Windows Task Scheduler
- Два триггера: при входе пользователя и ежедневно в заданное время
- Автоматическое создание ZIP-архивов с датой и временем

### 📁 **Поддержка различных источников данных**
- Стандартные папки Windows (Desktop, Documents)
- Пользовательские директории через конфигурационный файл
- Гибкая система исключений файлов по маскам

### 🔧 **Централизованное управление**
- Обновление скриптов и конфигурации из сетевой папки
- Единая конфигурация для всех пользователей
- Возможность изменения параметров без переустановки

### 🛡️ **Контроль ресурсов**
- Ограничение максимального размера источников
- Проверка свободного места на целевом диске
- Ограничение времени выполнения задач

### 📊 **Мониторинг и логирование**
- Детальные журналы работы (Launcher.log и UserBackup.log)
- GUI-уведомления для критических ошибок
- Автоматическая ротация логов

### ⚙️ **Гибкая конфигурация**
- JSON-конфигурация с поддержкой UTF-8
- Локализованные сообщения на русском языке
- Настройка всех аспектов работы через конфигурационный файл

## 📥 Установка и настройка

### Быстрая установка

```cmd
# Двойной клик по файлу или из командной строки
Install-UserBackup.cmd
```

### Расширенная установка

```powershell
# Ручной запуск с параметрами
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\Install-UserBackup.ps1 -ConfigPath "D:\Config\BackupConfig.json" -Diagnostic
```

### Процесс установки

1. **Проверка зависимостей**
   - Проверка наличия Windows PowerShell 5.1+
   - Валидация синтаксиса всех скриптов PowerShell

2. **Копирование файлов**
   - Все скрипты копируются в `%LOCALAPPDATA%\ASUP\UserBackup\`
   - Сохранение существующего `LocalDirectoriesToBackup.lst`

3. **Регистрация задачи**
   - Создание задачи в Windows Task Scheduler
   - Настройка триггеров (при входе + ежедневно)
   - Установка ограничений выполнения

4. **Валидация**
   - Проверка созданной задачи
   - Запись результата в журнал

### Требования к среде

- **ОС**: Windows 7/8/10/11, Windows Server 2012+
- **PowerShell**: версия 5.1 или выше
- **Права**: Стандартные права пользователя (обычно без прав администратора)
- **Сеть**: Доступ к сетевой папке для обновлений (опционально)

## ⚙️ Конфигурация

### Основной конфигурационный файл (`BackupConfig.json`)

```json
{
  "Install": {
    "LocalSubdirectory": "ASUP\\UserBackup"
  },
  "Task": {
    "Name": "Backup Task",
    "Path": "\\ASUP\\User BackUp Manager\\",
    "ManagedNames": ["Backup Task", "User BackUp Manager"],
    "DelayMinutes": 3,
    "DailyRunTime": "01:00",
    "ExecutionTimeLimitHours": 6
  },
  "Update": {
    "NetworkPath": "\\\\FS-01\\Scripts\\UserBackupManager\\",
    "WorkerFileName": "Backup-UserData.ps1",
    "LauncherFileName": "Launcher-UserBackup.ps1",
    "TaskRegistrarFileName": "Register-UserBackupTask.ps1",
    "ConfigFileName": "BackupConfig.json",
    "ContinueOnFailure": true,
    "ShowWarningOnFailure": true
  },
  "Backup": {
    "RootPath": "D:\\_BackUp_",
    "HideRootFolder": true,
    "CopiesToKeep": 2,
    "MaxSourceSizeMB": 700,
    "ScheduleMode": "Daily",
    "SafetyReserveMB": 64,
    "ExcludeMasks": ["*.tmp", "~$*", "*.mp3", "*.mp4"]
  }
}
```

### Ключевые параметры

#### Задача планировщика (`Task`)
- **`Name`**: Имя задачи в планировщике
- **`Path`**: Путь к задаче (должен начинаться и заканчиваться `\`)
- **`DelayMinutes`**: Задержка после входа пользователя (1-1440 минут)
- **`DailyRunTime`**: Время ежедневного запуска (формат HH:mm)

#### Обновление (`Update`)
- **`NetworkPath`**: Сетевая папка для обновлений
- **`ContinueOnFailure`**: Продолжать работу при ошибке обновления
- **`ShowWarningOnFailure`**: Показывать предупреждение при ошибке

#### Резервное копирование (`Backup`)
- **`RootPath`**: Корневая папка для архивов
- **`CopiesToKeep`**: Количество сохраняемых копий (минимум 1)
- **`MaxSourceSizeMB`**: Максимальный размер источника в МБ
- **`ScheduleMode`**: Режим расписания (`Daily` или `Weekly`)

### Пользовательские директории (`LocalDirectoriesToBackup.lst`)

```
:: Включить или отключить список - True / False
True

Pictures
Links
Downloads\Projects
```

**Формат**:
1. Первая строка: комментарий (необязательно)
2. Вторая строка: `True` (включено) или `False` (отключено)
3. Последующие строки: относительные пути от `%USERPROFILE%`

## 🔄 Обновление

### Централизованное обновление

Система поддерживает обновление всех ключевых компонентов из сетевой папки:

**Обновляемые файлы**:
- ✅ `BackupConfig.json` - Конфигурация
- ✅ `Backup-UserData.ps1` - Рабочий скрипт
- ✅ `Register-UserBackupTask.ps1` - Регистратор задач
- ✅ `LocalDirectoriesToBackup.lst` - Список директорий
- ✅ `Launcher-UserBackup.ps1` - Сам лаунчер
- ✅ `Install-UserBackup.ps1` - Скрипт установки
- ✅ `Uninstall-UserBackup.ps1` - Скрипт удаления

### Процесс обновления

1. **Проверка доступности** сети и сетевой папки
2. **Загрузка файлов** во временное хранилище
3. **Валидация** синтаксиса PowerShell скриптов
4. **Сравнение** с текущими версиями (хеш SHA-256)
5. **Транзакционное обновление** с поддержкой отката
6. **Перерегистрация задачи** с новыми параметрами

### Настройка сетевой папки

1. Создайте сетевую папку (например, `\\FS-01\Scripts\UserBackupManager\`)
2. Разместите в ней актуальные версии файлов:
   ```
   Backup-UserData.ps1
   Register-UserBackupTask.ps1
   Launcher-UserBackup.ps1
   BackupConfig.json
   LocalDirectoriesToBackup.lst
   Install-UserBackup.ps1
   Uninstall-UserBackup.ps1
   ```
3. Настройте права доступа:
   - **Чтение**: Все пользователи
   - **Запись**: Только администраторы АСУП

### Распространенные проблемы

#### Задача не запускается
```powershell
# Проверка состояния задачи
$task = Get-ScheduledTask -TaskName "Backup Task" -ErrorAction SilentlyContinue
if ($task) {
    Write-Host "Состояние: $($task.State)"
    Write-Host "Последний запуск: $($task.LastRunTime)"
} else {
    Write-Host "Задача не найдена"
}
```

#### Ошибки обновления
1. Проверьте доступность сетевой папки
2. Убедитесь в правильности настроек `Update.NetworkPath`
3. Проверьте права доступа к сетевой папке

#### Недостаточно места
```powershell
# Проверка свободного места
$drive = (Get-PSDrive -Name D).Free / 1GB
Write-Host "Свободно на диске D: $drive GB"
```

## 🛡️ Безопасность

### Принципы безопасности

1. **Минимальные привилегии**
   - Работа под учетной записью пользователя
   - Без прав администратора по умолчанию

2. **Валидация кода**
   - Проверка синтаксиса всех PowerShell скриптов
   - Валидация JSON конфигурации
   - Проверка хешей SHA-256 при обновлении

3. **Транзакционность**
   - Откат при ошибках обновления
   - Сохранение предыдущих версий файлов
   - Восстановление при сбоях

4. **Изоляция данных**
   - Отдельные папки для каждого пользователя
   - Ограничение доступа к архивам других пользователей
   - Шифрование не применяется (архивы в открытом виде)

### Рекомендации по безопасности

1. **Сетевая папка**
   - Ограничьте запись только администраторам
   - Используйте доменную аутентификацию
   - Регулярно проверяйте содержимое на отсутствие вредоносного кода

2. **Архивы**
   - Регулярно переносите архивы на защищенное хранилище
   - Рассмотрите возможность шифрования конфиденциальных данных
   - Установите политики хранения архивов

3. **Мониторинг**
   - Регулярно проверяйте журналы на предмет ошибок
   - Мониторинг использования дискового пространства
   - Аудит доступа к сетевым ресурсам

## ❓ Часто задаваемые вопросы

### Q: Нужны ли права администратора для установки?
**A**: Обычно нет. Система работает под учетной записью пользователя. Однако доменные политики могут ограничивать создание задач в планировщике.

### Q: Как добавить дополнительные папки для резервного копирования?
**A**: Добавьте пути в файл `LocalDirectoriesToBackup.lst` в формате относительных путей от `%USERPROFILE%`.

### Q: Что делать, если архивов стало слишком много?
**A**: Настройте параметр `Backup.CopiesToKeep` в конфигурации. Старые архивы будут автоматически удаляться.

### Q: Как отключить резервное копирование на время?
**A**: Установите `"ScheduleMode": "Weekly"` и настройте день, который не наступит в ближайшее время, или временно удалите задачу через планировщик.

### Q: Система пишет "Недостаточно места", но место есть
**A**: Проверьте параметр `Backup.SafetyReserveMB` - система резервирует дополнительное место.

### Q: Как изменить время ежедневного запуска?
**A**: Измените параметр `Task.DailyRunTime` в формате HH:mm (24-часовой формат).

## 📋 Технические требования

### Системные требования
- **Операционная система**: Windows 7 SP1 / Windows Server 2012 R2 или выше
- **PowerShell**: Версия 5.1 или выше
- **.NET Framework**: 4.5 или выше (для некоторых функций)
- **Место на диске**: Зависит от объема резервных копий + 64 МБ резерв

### Рекомендуемые конфигурации
- **Процессор**: 1 GHz или выше
- **Оперативная память**: 512 МБ (минимум), 2 ГБ (рекомендуется)
- **Дисковое пространство**: В 2 раза больше размера резервируемых данных
- **Сеть**: 100 Мбит/с или выше для обновлений из сетевой папки

### Поддерживаемые файловые системы
- NTFS (рекомендуется)
- ReFS
- FAT32 (с ограничениями на размер файлов)

### Ограничения
- **Максимальный размер источника**: 700 МБ по умолчанию (настраивается)
- **Количество сохраняемых копий**: 2 по умолчанию (настраивается)
- **Максимальное время выполнения**: 6 часов по умолчанию (настраивается)
- **Количество пользовательских директорий**: Не ограничено
