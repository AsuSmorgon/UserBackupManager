# Резервное копирование профиля Windows

## Состав проекта

- `Install-UserBackup.cmd` — рекомендуемый запуск PowerShell-установщика с временной политикой `ExecutionPolicy Bypass`;
- `Install-UserBackup.ps1` — развёртывание локальных файлов и вызов регистратора задания;
- `Uninstall-UserBackup.cmd` — рекомендуемый интерактивный запуск деинсталлятора;
- `Uninstall-UserBackup.ps1` — удаление связанных заданий и локальных файлов приложения;
- `Register-UserBackupTask.ps1` — удаление старых управляемых заданий и создание единственной актуальной копии;
- `Launcher-UserBackup.ps1` — обновление worker-файла, регистратора и конфигурации из сетевой папки, затем запуск резервного копирования;
- `Backup-UserData.ps1` — проверки, архивирование и ротация;
- `BackupConfig.json` — все настройки и русские GUI-сообщения;
- `LocalDirectoriesToBackup.lst` — локальный список дополнительных каталогов пользователя;
- `README.md` — документация.

Скрипты рассчитаны на Windows PowerShell 5.1.

## Подготовка сетевой папки

По умолчанию лаунчер ищет обновления в:

```text
\\FS-00\Scripts\BackUpMng
```

Поместите в эту папку актуальные файлы:

```text
Backup-UserData.ps1
Register-UserBackupTask.ps1
BackupConfig.json
```

Лаунчер сначала копирует эти три файла во временные локальные файлы, проверяет структуру JSON и синтаксис обоих скриптов, затем сравнивает SHA-256 с локальными версиями. Если изменений нет, файлы и задание не перезаписываются. При реальном изменении лаунчер транзакционно заменяет worker, регистратор и конфигурацию, после чего вызывает обновлённый регистратор задания. При ошибке замены или регистрации восстанавливаются предыдущие локальные файлы и предыдущие задания.

`LocalDirectoriesToBackup.lst` не входит в сетевой пакет обновления: лаунчер не ищет, не копирует, не сравнивает и не заменяет этот файл, даже если одноимённый файл находится на сетевой шаре.

Сетевая папка является доверенным источником исполняемого кода. Ограничьте право записи в неё администраторами АСУП, включите штатную защиту SMB домена и не предоставляйте пользователям право изменения файлов обновления.

Если сеть или сетевая папка недоступна, GUI-сообщение не показывается: причина записывается только в локальный `%LOCALAPPDATA%\ASUP\UserBackup\Launcher.log`, после чего запускается последняя локальная версия. Это правило не изменяется настройками. Параметры `Update.ContinueOnFailure` и `Update.ShowWarningOnFailure` управляют fallback и отображением только остальных, несетевых ошибок обновления.

`Launcher-UserBackup.ps1` не обновляет сам себя из сетевой папки. После изменения лаунчера обязательно повторно запустите `Install-UserBackup.cmd`, чтобы заменить локальную копию в `%LOCALAPPDATA%\ASUP\UserBackup`. Worker, конфигурация и `Register-UserBackupTask.ps1` обновляются из сетевой папки автоматически.

После установки запустите задание или дождитесь следующего входа и откройте `%LOCALAPPDATA%\ASUP\UserBackup\Launcher.log`. Актуальная версия записывает строку `Launcher started. Version=2026.09.15.1.`. Если такой строки нет, планировщик всё ещё запускает старую локальную копию.

## Установка

Запустите `Install-UserBackup.cmd` двойным щелчком либо из командной строки от имени пользователя, для которого требуется резервное копирование:

```cmd
Install-UserBackup.cmd
```

При запуске без аргументов CMD-файл выбирает `BackupConfig.json`, расположенный в одной папке с ним, проверяет наличие файла и явно передаёт его установщику через `-ConfigPath`. После завершения установки или вывода ошибки окно ожидает нажатия любой клавиши, чтобы пользователь успел прочитать результат. Если соседний конфигурационный файл отсутствует, CMD завершается с кодом `4` после ожидания клавиши.

При запуске с явным `-ConfigPath` или другими аргументами ожидание клавиши отключено, поэтому CMD можно использовать в автоматизированных сценариях.

CMD-файл использует штатный Windows PowerShell и передаёт параметр `-ExecutionPolicy Bypass` только создаваемому процессу установщика. Системная и пользовательская политика выполнения PowerShell при этом не изменяются.

Дополнительные параметры передаются непосредственно `Install-UserBackup.ps1`. Например, для другого файла конфигурации:

```cmd
Install-UserBackup.cmd -ConfigPath "D:\Config\BackupConfig.json"
```

Альтернативный ручной запуск без CMD:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\Install-UserBackup.ps1
```

Установщик:

1. читает `BackupConfig.json`;
2. проверяет синтаксис worker-файла, лаунчера и регистратора задания;
3. копирует `Backup-UserData.ps1`, `Launcher-UserBackup.ps1`, `Register-UserBackupTask.ps1` и `BackupConfig.json` в `%LOCALAPPDATA%\ASUP\UserBackup`;
4. если локальный `LocalDirectoriesToBackup.lst` отсутствует, копирует первоначальный шаблон из папки установщика;
5. если локальный список уже существует, сохраняет его без изменений;
6. вызывает локальный `Register-UserBackupTask.ps1`;
7. регистратор удаляет старые управляемые копии задания;
8. создаёт одну актуальную копию с запуском через 3 минуты после входа и ежедневно в `01:00`.

Повторный запуск установщика обновляет локальные файлы и пересоздаёт задание. После успешного фактического обновления worker/config/регистратора из сетевой папки лаунчер также автоматически пересоздаёт задание с актуальными параметрами. Если изменён только локальный файл либо сам `Launcher-UserBackup.ps1`, необходимо повторно выполнить `Install-UserBackup.cmd`. Обычно права администратора не требуются. Доменная политика может запрещать пользователю создавать задания планировщика.

## Локальный список дополнительных каталогов

Локальный файл находится здесь:

```text
%LOCALAPPDATA%\ASUP\UserBackup\LocalDirectoriesToBackup.lst
```

Формат по умолчанию:

```text
:: Enable or Disable this list - True / False
True

Pictures
Links
```

Обрабатываются только строки, начиная с третьей. Список активен, только если после удаления пробелов значение **второй строки** равно `True` без учёта регистра. Любое другое значение, включая `False`, отключает весь список. Пустые строки и дополнительные строки-комментарии, начинающиеся с `::`, пропускаются.

Правила путей:

- относительные пути разрешаются от `%USERPROFILE%`: `Pictures` означает `%USERPROFILE%\Pictures`;
- абсолютные пути должны указывать на локальный диск, например `E:\Projects`;
- переменные окружения вида `%USERPROFILE%` раскрываются;
- UNC-пути, wildcard-маски, повторяющиеся пути и относительный выход через `..` за пределы профиля запрещены;
- источник не может совпадать с `Backup.RootPath`, содержать папку бэкапа или находиться внутри неё;
- отсутствующий каталог вызывает обычную ошибку резервного копирования, когда требуется новый архив;
- отсутствие самого `.lst` равнозначно отключённому списку.

Каждая активная запись обрабатывается как отдельный источник наравне с Desktop и Documents. Имя источника формируется из имени каталога. При совпадении с другим source name добавляется короткий хеш полного пути. Например, стандартные записи создают архивы `yyyyMMdd_HHmmss_Pictures.zip` и `yyyyMMdd_HHmmss_Links.zip`.

Файл должен быть сохранён в UTF-8. Повторная установка не перезаписывает существующий локальный список. Чтобы вернуть шаблон по умолчанию, удалите локальный `.lst` и повторно запустите установщик.

## Результат работы

Корневая папка по умолчанию:

```text
D:\_BackUp_
```

При первом резервном копировании она создаётся автоматически и получает атрибут `Hidden`. Для каждого пользователя создаётся вложенная папка:

```text
D:\_BackUp_\USERNAME\
```

Каждый источник сохраняется в отдельный архив. Имя содержит только дату, время и источник:

```text
20260910_153000_Desktop.zip
20260910_153000_Documents.zip
20260910_153000_Pictures.zip
20260910_153000_Links.zip
```

По умолчанию отдельно для каждого активного источника сохраняются две последние копии. Если путь удалить из локального списка, его старые архивы перестают участвовать в автоматической ротации и при необходимости удаляются вручную. Рабочий журнал резервного копирования находится в пользовательской папке и называется `UserBackup.log`. Лаунчер ведёт отдельный локальный журнал `%LOCALAPPDATA%\ASUP\UserBackup\Launcher.log`, включая ошибки доступа к сетевой папке. В начале каждой новой сессии в соответствующий журнал добавляется пустая строка для визуального разделения запусков. Размер одного файла журнала ограничен 1 МБ; по умолчанию сохраняются пять файлов каждого журнала.

GUI-сообщения отображаются в многострочном текстовом поле только для чтения. Текст можно выделить и скопировать сочетанием `Ctrl+C` либо кнопкой `Копировать`. Подписи кнопок задаются в `Messages.CopyButtonText` и `Messages.CloseButtonText`.

## Проверка периодичности

Задание планировщика имеет два триггера: после входа пользователя с задержкой `Task.DelayMinutes` и ежедневно во время `Task.DailyRunTime` (`01:00` по умолчанию). Ежедневный триггер позволяет создавать копии на компьютере, который долго работает без перезагрузки. Настройка `StartWhenAvailable` запускает пропущенное задание после пробуждения или появления доступной интерактивной сессии пользователя. Параллельный повторный запуск блокируется настройкой `IgnoreNew`.

Перед регистрацией `Register-UserBackupTask.ps1` находит старые управляемые задания текущего пользователя только в настроенном `Task.Path`, экспортирует XML в локальную rollback-папку и удаляет старые definitions. Затем создаётся и проверяется ровно одно актуальное задание. Управляемыми считаются задания с именами из `Task.ManagedNames`, служебным маркером АСУП либо точным действием PowerShell, запускающим локальный лаунчер и конфигурацию; во всех случаях проверяются текущий пользователь и TaskPath. При переименовании задания оставьте прежнее имя в `Task.ManagedNames`, чтобы оно гарантированно удалялось. XML удаляется после успешного commit или восстановления; при ошибке rollback сохраняется для ручного восстановления.

Оба триггера запускают лаунчер, после чего рабочий скрипт применяет режим резервного копирования. Параметр `Backup.ScheduleMode` поддерживает значения:

- `Daily` — не более одного полного комплекта архивов в день; режим включён по умолчанию;
- `Weekly` — запуск архивирования только в день `Backup.WeeklyDay`, по умолчанию в понедельник (`Monday`).

До проверки папок источников, их размера и свободного места скрипт читает активный локальный список и ищет полный комплект архивов всех источников с текущей датой. Архив считается существующим только тогда, когда ZIP открывается без ошибки и содержит корневой каталог соответствующего источника. Если пригодный комплект уже существует, дальнейшие проверки и архивирование пропускаются. Добавление пути в активный `.lst` делает комплект неполным и запускает новый полный цикл; отключённый список не участвует в проверке.

## Ограничение размера источников

Для каждого источника, включая каталоги из `LocalDirectoriesToBackup.lst`, отдельно рассчитывается размер файлов, оставшихся после применения масок исключения. Значение `Backup.MaxSourceSizeMB` по умолчанию равно `700` МБ.

Если хотя бы один источник превышает порог, архивирование не выполняется, а пользователь получает GUI-предупреждение с просьбой обратиться в отдел АСУП.

Перед записью также проверяется свободное место на целевом диске. Расчёт учитывает общий объём источников и резерв `Backup.SafetyReserveMB`. При недостатке места пользователь получает соответствующее GUI-сообщение.

## Маски исключения

Массив `Backup.ExcludeMasks` содержит wildcard-маски PowerShell. Маска проверяется как по имени файла, так и по относительному пути внутри каждого источника, включая каталоги из локального списка.

По умолчанию исключаются:

- временные файлы: `*.tmp`, `~$*`;
- аудио: `*.mp3`, `*.wav`, `*.wma`, `*.aac`, `*.m4a`, `*.flac`, `*.ogg`, `*.opus`;
- видео: `*.mp4`, `*.m4v`, `*.avi`, `*.mkv`, `*.mov`, `*.wmv`, `*.mpg`, `*.mpeg`, `*.webm`, `*.3gp`, `*.ts`, `*.mts`.

Изображения и фотографии не входят в стандартные исключения и архивируются.

Полный редактируемый список находится в `Backup.ExcludeMasks` файла `BackupConfig.json`.

Примеры дополнительных масок:

```json
"ExcludeMasks": [
  "*.tmp",
  "*.bak",
  "~$*",
  "Cache\\*",
  "Temp\\*"
]
```

Для отключения исключений используйте пустой массив:

```json
"ExcludeMasks": []
```

## Основные настройки `BackupConfig.json`

- `Install.LocalSubdirectory` — локальная папка относительно `%LOCALAPPDATA%`;
- `Task.Name` — актуальное имя задания планировщика;
- `Task.Path` — путь задания; поддерживается корень `\\`;
- `Task.ManagedNames` — актуальное и прежние имена управляемых заданий, которые нужно очищать;
- `Task.DelayMinutes` — задержка после входа пользователя;
- `Task.DailyRunTime` — время ежедневного запуска лаунчера в формате `HH:mm`, по умолчанию `01:00`;
- `Task.ExecutionTimeLimitHours` — максимальное время одного запуска задания;
- `Update.NetworkPath` — сетевой источник обновлений;
- `Update.WorkerFileName` — имя рабочего скрипта;
- `Update.LauncherFileName` — имя локального лаунчера, изменяется только установщиком;
- `Update.TaskRegistrarFileName` — имя обновляемого скрипта регистрации задания;
- `Update.ConfigFileName` — имя конфигурации, изменяется только установщиком;
- `Update.ContinueOnFailure` — разрешить локальный запуск при ошибке обновления;
- `Update.ShowWarningOnFailure` — показывать GUI только для несетевых ошибок обновления;
- `Backup.RootPath` — корневая папка резервных копий;
- `Backup.HideRootFolder` — устанавливать атрибут `Hidden`;
- `Backup.CopiesToKeep` — число копий каждого источника;
- `Backup.MaxSourceSizeMB` — максимальный размер одного источника;
- `Backup.ScheduleMode` — `Daily` или `Weekly`;
- `Backup.WeeklyDay` — день недельного запуска;
- `Backup.ExcludeMasks` — маски исключаемых файлов;
- `Backup.Sources` — список встроенных известных папок Windows; дополнительные локальные пути задаются только в `LocalDirectoriesToBackup.lst`;
- `Logging.MaxFileSizeMB` и `Logging.FilesToKeep` — параметры ротации обоих журналов;
- `Logging.LauncherFileName` — имя локального журнала лаунчера;
- `Messages` — все тексты, заголовки и подписи кнопок GUI на русском языке.

Файл необходимо сохранять в UTF-8. После изменения конфигурации опубликуйте её в сетевой папке. При следующем запуске лаунчер обновит локальную копию.

## Удаление

Перед удалением можно посмотреть план действий без внесения изменений:

```cmd
Uninstall-UserBackup.cmd -WhatIf
```

Для полного удаления запустите:

```cmd
Uninstall-UserBackup.cmd
```

При запуске без аргументов CMD использует соседний `BackupConfig.json` и ждёт нажатия любой клавиши после завершения. При наличии аргументов ожидание отключено.

Деинсталлятор:

1. читает проектную и, если она доступна, установленную конфигурацию;
2. находит все связанные задания текущего пользователя по `Task.ManagedNames`, служебному маркеру АСУП или точному действию лаунчера;
3. останавливает активные экземпляры найденных заданий;
4. удаляет все найденные definitions из планировщика;
5. только после успешной очистки заданий удаляет `%LOCALAPPDATA%\ASUP\UserBackup` со скриптами, JSON, журналами и пользовательским `LocalDirectoriesToBackup.lst`.

Если хотя бы одно связанное задание удалить не удалось, локальные файлы сохраняются, чтобы оставшееся задание не ссылалось на отсутствующий лаунчер.

Для нестандартной конфигурации или каталога установки:

```cmd
Uninstall-UserBackup.cmd -ConfigPath "D:\Config\BackupConfig.json"
```

```cmd
Uninstall-UserBackup.cmd -ConfigPath "D:\Config\BackupConfig.json" -InstallDirectory "C:\Users\USER\AppData\Local\ASUP\UserBackup"
```

Параметр `-InstallDirectory` принимается только для дочернего каталога `%LOCALAPPDATA%`; удаление самого `%LOCALAPPDATA%` или пути за его пределами блокируется.

Архивы из `D:\_BackUp_` деинсталлятор **не удаляет**. При необходимости сохранить пользовательский `LocalDirectoriesToBackup.lst`, скопируйте его до запуска деинсталляции.
